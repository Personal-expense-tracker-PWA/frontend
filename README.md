# Daily Expense Tracker (PWA)

A personal, single-user daily expense tracker. Installable on a phone via
"Add to Home Screen" so it behaves like a native app — PIN-locked, works
offline, no browser chrome.

## Tech stack

- **Frontend**: React + Vite + Tailwind CSS, installable PWA (`vite-plugin-pwa`), Recharts for charts
- **Backend**: Node.js + Express REST API
- **Database**: SQLite via `better-sqlite3` (single file, no server to run)
- **Auth**: 4-6 digit PIN, hashed with `bcryptjs`, session via signed JWT

## Project structure

```
backend/     Express API + SQLite database
frontend/    React PWA (Vite + Tailwind)
```

Each has its own `package.json`, `.env.example`, and runs independently.

## 1. Run it locally

### Backend

```bash
cd backend
npm install
cp .env.example .env      # edit JWT_SECRET to a long random string
npm run dev                # http://localhost:4000
```

The SQLite file is created automatically at `DB_PATH` (default `./data/expenses.db`)
on first run, along with the default categories (Food, Transport, Bills,
Shopping, Health, Entertainment, Other).

### Frontend

In a second terminal:

```bash
cd frontend
npm install
cp .env.example .env      # VITE_API_URL should point at your backend
npm run dev                 # http://localhost:5173
```

Open `http://localhost:5173` in a browser. The first time you open it you'll
be asked to set a PIN — that's the only "account" this app has.

## 2. How the app works

- **Home** — today/week/month totals, expenses grouped by date. Tap the
  floating `+` button, type an amount, and tap a category to save instantly
  (2 taps). "More details" reveals date, payment method, and a note.
- **Reports** — month picker, spend-by-category donut chart, daily trend
  line chart, and filters by category/payment method/note search.
- **Settings** — change PIN, change currency symbol, manage categories
  (rename/delete with reassignment if a category is in use), export to CSV,
  and export/import a full JSON backup.
- **Offline** — if a save fails because the network is down, it's queued in
  `localStorage` and retried automatically once you're back online. A banner
  at the top tells you when this is happening.

## 3. Deploying the backend (Render or Railway)

A `Dockerfile` and `render.yaml` are included in `backend/`.

**Render** (recommended, uses `render.yaml` as a Blueprint):

1. Push this repo to GitHub.
2. In Render, "New +" → "Blueprint", point it at the repo.
3. Render reads `backend/render.yaml`, builds the Docker image, and
   provisions a persistent disk mounted at `/app/data` so your SQLite file
   survives deploys/restarts.
4. `JWT_SECRET` is auto-generated by Render. Set `CORS_ORIGIN` to your
   deployed frontend URL (e.g. `https://your-app.vercel.app`) in the Render
   dashboard's environment variables.
5. Note the resulting API URL (e.g. `https://expense-tracker-api.onrender.com`).

**Railway**: create a new project from this repo, set the root directory to
`backend`, it will detect the `Dockerfile`. Add a volume mounted at
`/app/data` for persistence, and set `JWT_SECRET`, `DB_PATH=/app/data/expenses.db`,
and `CORS_ORIGIN` as environment variables.

> Without a persistent disk/volume, the SQLite file is wiped on every
> redeploy — make sure to attach one in production.

## 4. Deploying the frontend (Vercel or Netlify)

A `vercel.json` and `netlify.toml` are included in `frontend/`.

**Vercel**:

1. Import the repo, set the project root to `frontend`.
2. Framework preset: Vite. Build command `npm run build`, output `dist`
   (already configured in `vercel.json`).
3. Add environment variable `VITE_API_URL` pointing at your deployed backend,
   e.g. `https://expense-tracker-api.onrender.com/api`.
4. Deploy. Then go back to your backend's `CORS_ORIGIN` and set it to this
   Vercel URL.

**Netlify**: same idea — set base directory to `frontend`, it picks up
`netlify.toml` automatically. Set `VITE_API_URL` in Site settings →
Environment variables before building.

## 5. Installing it on an Android phone

1. Open the deployed frontend URL in **Chrome** on your Android phone.
2. Set your PIN when prompted (first launch only).
3. Tap the **⋮** menu (top-right of Chrome) → **Add to Home screen** (or
   Chrome may show an "Install app" banner automatically — tap it).
4. Confirm the name and tap **Add** / **Install**.
5. Open the app from your home screen icon — it launches full-screen, with
   no address bar, just like a native app.
6. On later opens you'll only need to re-enter your PIN if you didn't check
   "Remember me for 7 days" at login, or if more than 7 days have passed.

(On iPhone: open in Safari → Share icon → **Add to Home Screen**. iOS PWAs
work the same way but installs are triggered manually, there's no automatic
banner.)

## API overview

All routes are prefixed with `/api`. Every route except `/api/auth/*`
requires `Authorization: Bearer <token>`.

| Method | Path | Purpose |
|---|---|---|
| GET | `/auth/status` | Whether a PIN has been set yet |
| POST | `/auth/set-pin` | First-run PIN setup |
| POST | `/auth/verify-pin` | Log in, returns a token |
| POST | `/auth/change-pin` | Change PIN (auth required) |
| GET/POST | `/expenses` | List (with filters) / create |
| PUT/DELETE | `/expenses/:id` | Edit / delete an expense |
| GET/POST | `/categories` | List / create categories |
| PUT/DELETE | `/categories/:id` | Rename / delete (supports `?reassign_to=`) |
| GET | `/summary/dashboard` | Today/week/month totals |
| GET | `/summary/monthly` | Monthly total, by-category, daily trend |
| GET/PUT | `/settings` | Currency symbol |
| GET | `/export/csv` | Download expenses as CSV |
| GET | `/export/json` | Full JSON backup |
| POST | `/import/json` | Restore from a JSON backup (replaces existing data) |

## Notes

- `bcryptjs` (pure JS) is used instead of `bcrypt` to avoid native build
  requirements on the server — this only matters for local dev friction, the
  security properties are equivalent.
- The PWA manifest is generated as `manifest.json` (via `vite-plugin-pwa`) so
  the filename matches standard PWA conventions.
